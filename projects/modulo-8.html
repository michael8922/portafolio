Proyecto del curso · Módulos 6–8

API de usuarios y pedidos

Aplicación que evoluciona desde un servidor web hasta una API con autenticación, gestión de usuarios y pedidos y carga de imágenes.

Node.js · Express · PostgreSQL · Sequelize · JWT

Contexto y objetivo

Proyecto integrador del bootcamp para construir una aplicación de gestión de usuarios y pedidos. En el módulo 6 se desarrolló el servidor y las vistas; en el 7 se incorporaron PostgreSQL, relaciones y transacciones; en el 8 se añadió una API con autenticación y carga de imágenes.

Desafío y solución

El desafío técnico fue incorporar autenticación a una aplicación existente y proteger las operaciones que modifican datos. La solución agrega credenciales mediante una migración, verifica tokens JWT en middlewares y conserva la separación entre rutas, controladores, servicios y acceso a datos.

Arquitectura y herramientas

Interfaz web / Postman
          ↓
Rutas → Middlewares JWT → Controladores
                              ↓
                           Servicios
                              ↓
                Repositorios / Sequelize
                              ↓
                         PostgreSQL

Contraseñas procesadas con scrypt, JWT con HS256 y carga de imágenes con Multer. El panel guarda el token en sessionStorage. Las relaciones de datos incluyen usuario–perfil, usuario–pedidos y usuarios–roles; la aplicación no implementa autorización por roles.

Alcance técnico

  • CRUD de dos entidades principales: usuarios y pedidos.
  • Tres tipos de relaciones: 1:1, 1:N y N:M.
  • Imágenes JPEG, PNG y WebP, con tamaño máximo configurable.
  • Respuestas uniformes con status, message y data.

Estas cifras describen el alcance implementado; no representan métricas de rendimiento ni de uso real.

Aprendizajes y elección del caso

El proyecto reúne modelado relacional, separación de responsabilidades, validaciones y autenticación. Permite explicar cómo evolucionó una aplicación a través de tres entregas y por qué la protección debe aplicarse en el servidor.

Lo seleccioné como caso de estudio del curso porque integra sus etapas de backend y conecta con mi interés en desarrollar APIs e integrar sistemas.

Estado de validación

Se realizaron pruebas manuales de registro, login, CRUD, solicitudes con y sin token y carga de imágenes. Queda pendiente reunir las capturas y completar la verificación de expiración del token, tamaño excedido y recorrido completo de la interfaz. No se publican porcentajes de cobertura ni mejoras de rendimiento sin mediciones.
